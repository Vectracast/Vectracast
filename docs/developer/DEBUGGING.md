# 调试、测试与 CLI

所有命令从仓库根目录执行，使用 `npm run platform -- <命令>`。

设置 → 高级 → 开发模式可保持主窗口可见、保留查询。“自动重建”控制 `dev` 文件监听后的重建，重新启用会处理暂停期间的修改。构建状态与错误在高级设置的独立“构建状态”窗口查看；它展示最后一次构建时间，不代表进程健康检查。运行时查询错误仍在结果列表中显示，查询日志仅记录插件、命令、耗时和成功/失败。

| 命令 | 功能 |
| --- | --- |
| `create <目录> [--youdao]` | 创建离线或有道模板，目标目录必须不存在 |
| `pack <目录>` | 校验 manifest 并打包；输出文件路径 |
| `validate <目录>` | 当前与 pack 相同，也生成产物 |
| `install <文件> --accept-permissions` | 本地安装，明确接受声明权限 |
| `dev <目录> --accept-permissions` | 首次开发安装、监听、编译、热重载 |
| `list` | 列出 ID、版本、启用/开发状态 |
| `query <扩展ID> <命令ID> <文本>` | 通过真实 XPC 服务查询；输出 JSON items，错误非零退出 |
| `rollback <扩展ID>` | 交换当前和上一个版本 |
| `doctor` | 显示本地工具信息并运行 XPC 文件/网络隔离探针 |
| `inspect` | 打印 Safari Web Inspector 手工连接步骤，不自动附加 |
| `logs` | 读取最近宿主查询诊断记录 |

## 热重载和错误

监听忽略 dist、node_modules 和 .git。修改成功时重新安装，主窗口通过 SQLite data_version 检测更新。正在输入的查询重新执行。失败时终端打印编译/权限错误，旧安装保持可用。

日志位于数据目录 `runtime.jsonl`，约 1MB 时轮换覆盖；只记录扩展 ID、命令、耗时、成功/失败，不记录查询、响应正文或密钥。目前 console.log/warn/error 不转发，扩展错误消息会显示于结果列表，不包含可点击的源码定位。CLI query 的标准输出可能包含你所查询的内容，请自行决定是否保存。

## 断点入口（待人工验收）

开发安装启用 `JSContext.isInspectable`，生产式本地安装关闭它。打包内嵌 source map 与 TypeScript 源码。

1. 使用 dev 安装扩展。
2. Safari 设置中启用开发者功能。
3. 在 Vectracast 触发查询后，从 Safari“开发 → 此 Mac”寻找 `Vectracast Extension`。
4. 打开 main.js 或映射源码并设置断点。

目前每次查询创建新 JSContext，短查询的附加窗口很短；15 秒 watchdog 仍启用，断点暂停可能导致服务超时。尚未完成稳定附加、TypeScript 行映射和暂停恢复的人工验证，**不能把这一入口视为完整的可用调试器**。下一步应加入仅限开发安装的等待附加模式和受控超时策略，再完成验收。

## 自动验证

```sh
npm run app:build
npm run check:platform
npm run test:platform
```

测试使用临时 LAUNCHER_HOME 数据库，通过实际签名的 App 内二进制启动 XPC。覆盖权限隔离、结果过滤、安装损坏、版本更新/回滚、冲突、死循环恢复、CLI 热重载及有道签名/解析。死循环测试约耗时 16 秒。翻译单元测试使用明确标识的测试凭据和响应，不调用收费服务。

应用尚未具备自动更新渠道。改原生代码后先退出正在运行的 Vectracast，再重新构建并打开；扩展 TS 修改使用 dev 即可。

## 常见问题

- “命令不存在”：检查 manifest 命令 id 与 `defineSearchCommand` 一致，CLI 第三个位置参数是命令 id，非关键词。
- “相同版本”：普通安装版本不可变；提高版本号，或先以独立 ID 创建开发安装。
- “关键词冲突”：修改新扩展关键词，或在设置中停用旧扩展。
- “需要确认权限”：检查声明，再显式使用 `--accept-permissions`；监听期间不会自动接受权限变化。
- 有道未配置：在原生设置填写 ID 和密钥。钥匙串字段留空表示保留旧值，卸载会清除。
- 全局键无效：默认 `Control+Option+Space`；可在“设置 → 通用”重新录制；占用的组合会拒绝保存。
