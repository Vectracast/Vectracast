# 交付顺序、验收与待确认项

状态：用户已确认并启动开发。A+B 已有可运行预览，尚未全部验收；详见 [验证记录](../developer/VALIDATION.md)。

## 1. 阶段与依赖

| 阶段 | 交付内容 | 通过标准 |
| --- | --- | --- |
| A：技术验证与原生内核 | 全局窗口、中文输入、应用搜索、查询协议、执行服务与调试验证 | 独立 .app 可运行；输入/焦点正确；插件死循环不冻结宿主；形成沙箱与断点证据 |
| B：第一个扩展闭环 | 最小 SDK、创建/开发/打包/安装 CLI、有道扩展、复制动作 | 空目录创建 → 调试 → 打包 → 安装 → `yd apple` 主框直出 → 复制；同一路径可更新及回滚 |
| C：开发者预览 | 错误覆盖、source map、Testkit、完整教程、受支持的组件、可信脚本适配 | 非作者按文档能开发第二个扩展；错误能定位源码；兼容范围明确 |
| D：商店测试版 | 仓库、签名、分发、检索、详情、版本管理、作者/审核后台 | 两个版本经过真实审核、安装、升级与回滚；权限变化和坏包被正确处理 |
| E：日常工具与品质 | 文件、剪贴板、片段、笔记、窗口、主题、导入导出、稳定更新 | 高频场景可日常使用；原生交互和性能达到预算 |
| F：高级服务与生态 | AI、MCP、语音、自动化、同步、私有仓库 | 逐模块真实服务验收；离线、费用、权限、冲突与恢复可解释 |

这是依赖顺序，不是固定工期。A 阶段验证后才能给运行时、React 桥接、索引等高不确定项估算。完整目标保持不变，分阶段让每一版都可验收。

## 2. 第一版的定义

第一版指 A+B：可安装的 macOS 应用、统一主搜索、实时查询协议、最小 SDK 和 CLI、本地扩展安装、一个真实有道扩展、原生结果动作、错误处理、必要设置及从零可复现的文档。

这一版必须能独立运行。商店的本地包和版本模型从第一版开始使用；公开商店、完整 AI 系统和云同步在后续阶段交付。

验收要求真实查询结果、可运行的插件和独立宿主，静态界面不计为功能完成。

## 3. 核心验收用例

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| UX-01 | 全局快捷键唤起 | 输入焦点正确；关闭后回到原应用 |
| UX-02 | 中文输入法输入并按 Return 选词 | 完成选词，不误执行当前结果 |
| UX-03 | 连续输入 `yd apple` | 无需进入插件页面即显示真实结果 |
| UX-04 | 选择第二条翻译后回车 | 剪贴板只含第二条结果，不含来源标签 |
| UX-05 | `yd apple` 快速改成 `yd orange` | 迟到的 apple 响应不能覆盖 orange |
| UX-06 | 多屏、全屏应用、Spaces 切换 | 唤起位置与焦点归还符合设置 |
| EXT-01 | CLI 创建并修改扩展 | 热重载；编译错误时保留上个正常版本 |
| EXT-02 | 断点进入 query | 能看到 TypeScript 源码和变量 |
| EXT-03 | 扩展死循环/崩溃 | 宿主仍可关闭和检索；显示可恢复的错误 |
| EXT-04 | 查询阶段调用复制动作 | 被运行时拒绝，不改剪贴板 |
| EXT-05 | 扩展读取其他扩展密钥 | 被代理与存储隔离拒绝 |
| EXT-06 | 取消、超时、空结果、鉴权失败 | 各自有一致可理解的状态 |
| PKG-01 | 安装损坏包或穿越路径包 | 拒绝；原扩展及用户文件不受影响 |
| PKG-02 | 安装不兼容的 SDK 版本 | 明确说明版本要求 |
| PKG-03 | 更新新增网络域名 | 展示差异，未经确认不替换旧版 |
| PKG-04 | 数据迁移失败或更新后崩溃 | 可恢复上个可用版本及兼容数据 |
| DOC-01 | 新开发者只看文档完成示例 | 不依赖作者口头补充步骤 |
| STORE-01 | 发布并安装测试仓库扩展 | 使用真实产物、签名和版本状态 |

上表保留完整验收标准；已执行项目和剩余项目分别记录于验证文档。

## 4. 必须保留的交付证据

- 每个阶段的可运行产物、版本号和源码对应关系。
- 指定机器与系统版本下的操作录像/截图、延迟测量及失败复现。
- 安装、升级、回滚的真实记录，包含数据库迁移结果。
- 运行时越权、超时和崩溃恢复测试。
- SDK 示例、文档代码片段与 API schema 的 CI 结果。
- 功能完成状态统一为：未开始、开发中、可演示、已验证、可发布；不能把「有入口」写成「已完成」。
