# 扩展商店、安装与分发

状态：设计草案；目前没有商店服务、账号系统或公开部署。

## 1. 产品范围

用户端需要搜索、分类、详情、截图、发布者、权限、支持平台、版本要求、变更记录，以及安装、禁用、更新、回滚和卸载。

开发者端需要创建发布者身份、提交版本、查看构建与审核结果、管理发布渠道、撤回版本、转移维护权及接收问题反馈。

运营端需要审核队列、权限差异、源代码/依赖审查、举报处理、下架、签名密钥管理和审计记录。初期只做免费扩展和维护者审核；付费市场另行规划。

## 2. 先做仓库协议，再做商店页面

阶段一支持本地包。阶段二使用同一包格式和协议运行自有测试仓库。阶段三开放公开商店与作者后台。桌面内商店和网页商店共用服务，避免维护两套安装逻辑。

建议 API 草案：

| API | 用途 |
| --- | --- |
| `GET /v1/extensions?query=…` | 搜索及筛选 |
| `GET /v1/extensions/{id}` | 扩展详情与兼容版本 |
| `GET /v1/extensions/{id}/releases` | 不可变发布记录 |
| `POST /v1/update-checks` | 按已安装版本、系统及宿主版本批量检查 |
| `POST /v1/submissions` | 提交审核草稿 |
| `GET /v1/submissions/{id}` | 查看构建、审核状态 |
| `POST /v1/reports` | 举报或提交问题 |

服务器只接受已验证身份在其命名空间内提交包。客户端搜索不上传无关主框查询或本地文件索引。`publish` 的提交不等于批准公开发布。

## 3. 安装包与可信来源

拟议包扩展名：`.launcher-extension`，实质为受约束的归档文件；名称待品牌确认。

包包含 manifest、构建后 JS、静态资源、许可、版本说明、内容清单和构建元数据。依赖应在构建阶段打包；用户安装后不执行 npm install、postinstall 或任意下载脚本。

内容摘要用于完整性验证，**摘要本身不能证明发布者身份**。仓库签名覆盖扩展 ID、版本、文件摘要、SDK/宿主兼容区间、权限集合及发布渠道。客户端内置或显式信任仓库公钥；密钥轮换与撤销元数据也需要验证。

发布者账号用于确认提交权限，仓库审核通过后才签名分发。源码提交/构建记录与具体包摘要关联，确保审核对象就是分发对象。

未签名的本地开发包显示独立来源标记；不能通过填写相同 ID 冒充商店扩展，也不能覆盖已安装的商店身份。

## 4. 安装状态机

`下载 → 校验签名与摘要 → 检查宿主兼容 → 安全解包 → 校验 manifest → 展示权限 → 激活 → 健康检查`

任何一步失败，清理暂存区并保留原版本。归档检查拒绝路径穿越、指向包外的符号链接、过多文件和异常解压体积。安装包中的数据不作为宿主命令执行。

安装记录至少保存：来源、发布者身份、版本、包摘要、许可、权限授予、安装时间、运行时版本、数据 schema 和最后已知正常版本。

## 5. 更新与回滚

- 版本内容不可变；同一个版本不能在服务端替换文件。
- 同权限的小版本可按用户设置自动更新；新增权限、域名、运行模式时要求重新授权。
- 更新先进入暂存区，完成验证及必要数据迁移，再原子切换；切换失败继续运行旧版。
- 新版首次运行崩溃可以恢复上一个已知正常版本，防止持续启动崩溃。
- 数据迁移必须提供回滚策略；不能只有「换回旧 JS」，却让旧版读取不兼容数据库。
- 支持稳定版与测试版渠道，不混用 SDK 实验能力。
- 缓存的有效签名包离线可安装；客户端仍应展示离线时无法确认最新撤回状态的事实。
- 有撤回标记的版本停止新增安装；已安装用户收到明确原因与可用替代版本。普通下架不静默清除用户数据。

## 6. 发布审核

1. 身份、命名空间、许可和资源完整性检查。
2. 锁定构建环境，校验依赖与不支持的运行时 API。
3. manifest/schema 校验、类型检查、测试及示例运行。
4. 比较上个版本的权限、网络域名、入口和依赖变化。
5. 人工审核功能描述与代码是否一致，是否存在误导交互。
6. 构建并保存可追溯产物，通过测试渠道验证。
7. 批准发布、签名、生成不可变发布记录。

代码审核不能代替运行时隔离。公开商店上线前必须完成架构文档中的沙箱验证；若尚未达到门槛，只开放受控开发者预览，不宣传成可安全运行任意扩展。

## 7. 卸载与数据管理

禁用立即停止命令、任务和会话。卸载移除包与注册信息，并让用户选择保留或删除扩展数据和凭据。共享的系统权限是授予宿主应用的，不能在文案中伪称卸载一个扩展就撤回全部 macOS 授权。

开发模式包和商店包的数据默认隔离；开发测试不能覆写用户正式配置。导出默认不含密钥。

## 8. 商店页面验收

| 页面 | 必须真实工作的行为 |
| --- | --- |
| 搜索与分类 | 从仓库查询；显示加载、空结果、失败 |
| 详情 | 版本、发布者、权限、兼容性、截图与变更记录 |
| 安装 | 使用实际包分发链路；进度与失败原因可见 |
| 已安装 | 启用/禁用、设置、更新、回滚、卸载 |
| 作者后台 | 提交一个新版本并看到真实审核状态 |
| 审核后台 | 批准或拒绝；发布记录可追溯 |

只有能完成安装和版本生命周期的商店才通过验收；静态卡片、假下载按钮和写死的安装状态不算完成。
