# 插件底座：已确认的核心边界

Vectracast 是底座，用户功能全部由插件实现。这是后续开发的架构约束。

## 底座负责什么

- 窗口、全局唤起、输入法与焦点、键盘交互和结果/动作渲染。
- 命令发现、关键词与无关键词路由、去抖、取消、结果隔离与合并。
- 插件安装、启停、升级、回滚、卸载、权限、配置、日志和沙箱运行时。
- SDK、CLI、文档与调试支持。
- 经权限控制的系统能力接口：例如读取应用目录元数据、用户选择后打开应用、剪贴板、网络与密钥代理。

这些是所有插件共用的基础设施。底座可以封装原生系统 API，但不承载应用搜索的匹配/排序、计算器表达式解析、翻译规则等具体功能逻辑。

## 插件负责什么

| 用户功能 | 实现 |
| --- | --- |
| 插件目录搜索、分类、详情、安装／更新入口 | `extensions/plugin-store` |
| 剪贴板历史检索与展示 | `extensions/clipboard-history` |
| 应用搜索、匹配、排序 | `extensions/applications` |
| 算式计算与进制转换 | `extensions/calculator` |
| 有道翻译 | `extensions/youdao` |
| 文本转换 | `extensions/text-tools` |
| 后续文件搜索、窗口管理、AI、工作流等 | 均通过插件提供；所需系统接口按通用能力加入 SDK |

官方随附插件与第三方插件使用相同 manifest、SDK、运行时、权限及生命周期，不设绕过插件机制的官方功能分支。所有插件通过包安装，构建宿主本身不会把业务编译进可执行文件。应用资源携带商店安装包用于首次引导，用户确认权限后通过相同安装流程进入注册表。

空搜索、底座设置与本地插件生命周期管理属于底座自身的运行和维护界面。“发现插件”只打开或引导安装商店插件。停用所有功能插件后，本地安装与启停入口仍然可用；搜索、计算、翻译等结果不应继续出现。

## 入口与系统能力

- 关键词模式：例如 `yd 内容`，只路由给命中的插件命令。
- 无关键词模式：命令声明 `inputMode: "query"`，直接处理未被关键词接管的非空输入；不匹配时返回空结果。
- 高权限副作用只能通过声明的动作、由用户执行。插件不能在查询阶段直接启动应用或写入剪贴板。
- 原生能力返回的数据与动作目标由宿主校验。应用插件拿到的是应用 ID 和元数据，不能提交任意路径当作应用打开。
- 具体功能设置放在插件配置内；通用窗口、外观、快捷键与开发诊断属于底座设置。

## 开发检查

新增功能先建立插件。只有多个插件都可复用的原生能力或平台生命周期需要变更，才修改宿主和 SDK。每项迁移需验证：插件启用后功能可用，停用后结果消失，重新启用后恢复；其他插件仍正常。

## 插件商店边界

商店的搜索、分类、分组、详情文字、命令说明和动作菜单位于独立 TypeScript 插件。SDK 的 `catalog.list` 只提供已校验的目录快照、安装句柄和已安装版本；`catalog.install` 只能由用户执行，宿主再确认目标插件权限。传输、大小限制、SHA-256、manifest、原子安装与回滚是共用基础设施。

列表、分类筛选与全页详情是通用渲染接口，不按商店插件 ID 分支。禁用商店后这些搜索结果消失；本地安装与启停入口仍可用于恢复插件。
